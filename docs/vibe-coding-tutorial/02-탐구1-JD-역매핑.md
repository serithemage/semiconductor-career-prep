# 챕터 2: 탐구 1 — JD 역매핑 (병렬 에이전트의 위력)

> **소요**: 약 9분 (3개 에이전트 동시 실행)
> **리서치 투입**: 병렬 에이전트 3기
> **핵심 인사이트**: "증명해야 할 역량"은 상상이 아니라 **실제 채용공고(JD)에서 역산**한다. 그리고 회사별로 따로 조사할 땐 **AI 에이전트를 동시에 3개** 띄운다.

## Context
seed 상태의 INTENT.md는 What이 비어 있었다. 이걸 채우는 첫 탐구로 "삼성·SK하이닉스·NVIDIA의 채용공고에서 경영정보/전산 전공자가 갈 수 있는 직무와 자격요건"을 역매핑하기로 했다. status를 `seed → exploring`으로 올렸다.

## The Prompt
```
진행시켜
```
(단 한 마디. 앞선 인터뷰에서 "첫 탐구 = JD 역매핑"을 합의했기 때문에 짧은 신호로 충분했다.)

## What Happened
AI는 **3개의 조사 에이전트를 동시에** 띄웠다 — 삼성 / SK하이닉스 / NVIDIA 각 1기. 각 에이전트는 perplexity·웹검색으로 실제 채용 사이트·합격후기를 조사하고, "직무별 필수자격 = 증명해야 할 역량"을 표로 정리해 돌아왔다.

세 보고서가 한 번에 도착했고, AI는 이를 종합해 `docs/jd-reverse-mapping.md`로 저장하고 INTENT.md의 What·Learnings를 갱신했다.

## The Result
핵심 발견:
- **삼성**: SW개발(SW역량테스트 트랙), AI/IT인프라, 생산관리/SCM 등. 영어회화 필수.
- **SK하이닉스**: 신입 IT 직무기술서 모집전공에 **"경영정보학" 명시** → 정공법! IT직무는 C/C++ 코테.
- **NVIDIA**: 팹리스라 SW/AI 중심. 한국은 경력 SA 위주, 신입은 글로벌 NCG 우회.

## 🔧 Debugging: "에이전트가 환각을 섞었다"
**증상**: 조사 보고서 일부에 출처로 확인되지 않는 구체 수치가 섞임.
**근본 원인**: LLM 심층조사가 그럴듯한 숫자를 생성(환각).
**해결**: 이후 모든 조사 에이전트에게 **"확인된 사실 vs 추정"을 구분 표기하고 출처 URL 필수**를 지시. 보고서에서 환각 의심 항목을 배제.
**교훈**: AI 조사는 빠르지만, **출처 강제 + 사실/추정 구분**이 없으면 못 믿는다.

## Lessons Learned
- **"진행시켜" 한 마디로 3개 에이전트가 동시에 일한다** — 의도가 합의돼 있으면 짧은 신호로 큰 작업이 굴러간다.
- **JD 역매핑 = 취업 준비의 출발점**. 막연히 "코딩 잘하면 되겠지"가 아니라, 공고가 요구하는 역량을 문서에서 직접 뽑는다.
- 내 전공(경영정보/전산)이 **이미 모집전공에 명시**돼 있을 수 있다. "직무 매칭 모호함"의 절반은 정보 부족이었다.
