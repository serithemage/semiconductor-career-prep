# 챕터 4: 탐구 3 — 남은 물음표 마저 해소하기

> **소요**: 약 6분 (2개 에이전트 동시)
> **리서치 투입**: 병렬 에이전트 2기
> **핵심 인사이트**: 의도 문서의 `(?)` 표시는 "아직 모르는 것"의 정직한 표식. **물음표를 다 지우면 clarified로 갈 수 있다.**

## Context
INTENT.md의 What에는 아직 `(?)`가 붙은 두 항목이 있었다 — "AI 활용 워크플로의 형태"와 "반도체 도메인 모듈의 범위". 이 둘만 해소하면 의도가 명확해진다(clarified).

## The Prompt
```
남은 (?) 탐구 마저
```

## What Happened
2개 에이전트 동시 실행:
- 에이전트 1 — "취업 준비에서 AI(LLM)를 어떤 구체적 형태로 쓰는가" 조사
- 에이전트 2 — "비전공 IT 직무자에게 필요한 최소 반도체 도메인 지식 범위" 조사

## The Result
**AI 워크플로 4단계 확정** (`docs/ai-workflow.md`):
1. JD↔역량 갭분석 2. 포트폴리오 hard-to-fake 검증 3. 자소서 STAR refine(대필❌) 4. 코테·면접 대비
- 핵심 경계: **면접 전/후 AI 사용은 OK, 면접 중 실시간 AI는 치팅** → INTENT의 Not과 일관

**도메인 모듈 6개 확정** (`docs/domain-knowledge-module.md`):
- 제조 1분 브리핑 → 수율·불량 → 스마트팩토리 IT스택 → DS 특수성 → 회사별 맞춤
- 원칙: **"공정 개발 수준 ❌ → 데이터가 돈과 직결되는 이유를 IT 언어로 번역하는 수준"**
- "여기까지는 과함" 경계도 명확화(소자물리·회로설계는 비전공 범위 밖)

## Lessons Learned
- **`(?)`는 부끄러운 게 아니라 지도다.** 모르는 걸 명시해두면 "다음에 뭘 조사할지"가 저절로 보인다.
- AI 활용에도 **윤리 경계**가 있다. "refine은 OK, 창작·대필은 NOT"을 처음부터 박아두면 흔들리지 않는다.
- 비전공자가 반도체를 **다 알 필요 없다.** "어디까지가 과함"인지 선을 긋는 게 효율적 학습의 핵심.
