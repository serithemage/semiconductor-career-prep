# 챕터 7: 플래그십 프로젝트 빌드 가이드 만들기

> **소요**: 약 8분
> **핵심 인사이트**: 조사가 끝나면 **개요서로 비교 → 하나를 깊게**. 추상적 아이디어를 "AI에게 시킬 프롬프트 단위"의 빌드 가이드로 바꾼다.

## Context
탐구 4에서 프로젝트 후보 3개(A·B·C)가 나왔다. 전부 만들면 얕아진다. 먼저 1페이지 개요서로 비교하고, 하나를 골라 깊게 파기로 했다.

## The Prompts
```
3개 프로젝트 개요서 먼저
```
```
A를 깊게 빌드 가이드 만들어줘
```

## What Happened
**1) 개요서** (`content/portfolio-projects/overview.md`): A·B·C를 한눈 비교표 + 각 1페이지 스펙으로 정리. AI 권고는 "A(플래그십) + B(보완)".

**2) 프로젝트 A 빌드 가이드** (`content/portfolio-projects/project-a-build-guide.md`): WM-811K 웨이퍼맵 분류 + **공정원인 해석 리포트**를 10단계로. 바이브 코딩 전제라 각 단계를 둘로 나눴다:
- 🤖 **바이브 코딩 프롬프트** — AI에게 그대로 시킬 문장
- ✅ **내가 검증할 것** — 직접 확인하고 ADR에 남길 것

## The Result — 핵심 차별화: 6단계 "공정원인 해석 레이어"
분류 결과를 도메인 언어로 번역하는 룰을 코드로 구현:
- Edge-Ring → 식각 seal ring breach 의심 (날카로운 완전 원)
- Scratch → cassette 핸들링 (같은 slot 여러 웨이퍼 일관된 호)
> "정확도 99%"가 아니라 **"이 웨이퍼는 가장자리 링 밀도가 높고 경계가 날카로워 seal breach가 의심된다"**는 진단 리포트가 면접의 결정적 자료.

## Lessons Learned
- **개요서로 비교한 뒤 고르면** 자원을 한 곳에 집중할 수 있다. "3개 얕게 < 1개 깊게."
- 빌드 가이드를 **"AI에게 시킬 프롬프트 + 내가 검증할 것"으로 쪼개면** 비전공자도 따라 만들 수 있고, 동시에 "내 주도성"(검증·ADR)이 신호로 남는다.
- 정확도 수치는 가이드에 **일부러 비워뒀다** — 본인이 실제로 돌린 값만 기입(조작 금지 = Not 원칙).

## Try It Yourself
```
내 후보 프로젝트 [A/B/C]를 1페이지 개요서로 비교해줘.
그중 [A]를 골랐으니, 데이터 로드→모델→도메인 해석→배포→ADR까지
단계별 빌드 가이드를 만들어줘. 각 단계는 "AI에게 시킬 프롬프트"와
"내가 검증할 것"으로 나눠서. 정확도는 내가 실제로 돌려서 채울게.
```
