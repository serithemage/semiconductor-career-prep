## 프로젝트 A — Wafer Bin Map 분류 + 공정원인 해석 리포트 (플래그십)

### 문제 정의
웨이퍼 검사에서 나오는 **Wafer Bin Map(WBM)**의 불량 공간 패턴 9종을 자동 분류하고, 더 나아가 **"이 패턴은 어느 공정 단계의 어떤 원인에서 비롯됐는가"를 해석하는 진단 리포트**를 생성한다.

### 사용 데이터
- **WM-811K** (Kaggle `qingyi/wm811k-wafer-map`, CC0): 81만 웨이퍼맵, 9패턴(라벨 21%, 미라벨 63만)

### 핵심 기술 (바이브 코딩으로 단계 구현)
1. EDA·클래스 불균형 분석 → 2. CNN/ViT 분류기 → 3. **Grad-CAM으로 결함 위치 시각화** → 4. **패턴→공정원인 매핑 해석 레이어**(Edge-Ring→식각 seal breach 등) → 5. Streamlit/Gradio + HF Spaces 배포

### 왜 반도체 기업이 관심 갖나
WBM 공간분석은 수율개선 활동의 15~25% 기여. "정확도"가 아니라 **원인 공정을 빠르게 지목**하는 능력이 진짜 가치.

### hard-to-fake 요소 (이게 신호)
- 정확도 99%가 아니라 **오분류 사례 분석** + "Edge-Ring 분류 웨이퍼가 특정 식각 챔버 출신이고 seal breach 경계를 보였다"식 **물리 해석 리포트**
- 미라벨 63만장을 self-supervised로 활용하는 현실 시나리오(선택)
- ADR(왜 ViT? 왜 이 증강?) + 손수 만든 eval set

### 4주 빌드 (요약)
1주 EDA+불균형 / 2주 분류기+Grad-CAM / 3주 **공정원인 해석 레이어** / 4주 배포+리포트+30초 데모

### 산출물
GitHub repo(atomic 커밋) · HF Spaces 라이브 데모 · 공정원인 해석 리포트(PDF/노션) · ADR 문서

## 프로젝트 B — 공정 센서 기반 수율/불량 예측 (Large-P-Small-N 정공법)

### 문제 정의
반도체 공정 센서 591개로 웨이퍼 **pass/fail을 예측**하되, 변수(P)≫샘플(N)·결측·익명화·극심한 불균형이라는 **반도체 데이터의 지저분함을 정면 돌파**하는 과정을 보인다.

### 사용 데이터
- **SECOM** (UCI, CC BY 4.0): 591센서 × 1567행, 불량 6.8%, 결측 다수

### 핵심 기술
피처 선택(고차원)·결측 처리 → 클래스 불균형(SMOTE/cost-sensitive) → XGBoost/RF → **누수 방지 분할** → SHAP로 근본인자 발굴 → 불확실성 정량화

### 왜 반도체 기업이 관심 갖나
SK 양산기술 JD가 "Python 기반 SPC/ML, 결함분석" 명시. 수율 예측 0.5%p 향상 = 수천만 달러.

### hard-to-fake 요소
- 캐글 정제데이터가 아닌 **익명 591피처·결측·6.8% 불량을 다룬 흔적**
- "정확도" 대신 **balanced accuracy / recall / PR-AUC**로 불균형 정직하게 평가
- 데이터 누수를 어떻게 막았는지 + 실패 모드 문서

### 4주 빌드 (요약)
1주 EDA+결측/상수피처 정리 / 2주 피처선택+베이스라인 / 3주 불균형+튜닝+SHAP / 4주 평가리포트+배포

### 산출물
GitHub repo · 분석 노트북 · SHAP 근본인자 리포트 · 평가 방법론 문서(왜 PR-AUC인가)

## 프로젝트 C — WBM 유사사례 검색 기반 근본원인분석(RCA)

### 문제 정의
신규 웨이퍼맵을 입력하면 **과거 유사 불량 패턴 top-k + 추정 근본원인**을 검색해주는 RCA 보조 시스템. (DefectTrackNet식, 2025 최신 트렌드)

### 사용 데이터
- **WM-811K** + **MixedWM38** (혼합결함)

### 핵심 기술
WBM 임베딩(CNN feature/오토인코더) → **FAISS 벡터검색** → 도메인룰(패턴↔원인 매핑) 결합 → LLM으로 진단 설명 생성 → 대시보드

### 왜 반도체 기업이 관심 갖나
RCA 진단 시간 수일→수분, fab 가동률 5~8%↑. 삼성 Fab Automation·SK 빅데이터분석 직결.

### hard-to-fake 요소
- 단순 분류를 넘어 **검색+도메인룰+설명**의 시스템 통합(MIS 강점)
- 2025 RCA 논문 트렌드 반영 + LLM 활용을 "지시·검증" 기록으로 문서화

### 4주 빌드 (요약)
1주 임베딩 추출 / 2주 FAISS 검색+유사도 평가 / 3주 도메인룰+LLM 설명 / 4주 대시보드+배포

### 산출물
GitHub repo · 검색 데모(HF Spaces) · 도메인룰 매핑표 · 시스템 아키텍처 문서

## 공통 — 모든 프로젝트에 심을 5가지 신호 (2026 필수)
1. **지저분한 실데이터 처리** 흔적
2. **도메인 해석**(패턴↔공정 원인, Large-P-Small-N 등)
3. **정량 성과** — 구체적 작은 숫자(recall 0.71→0.89 등)
4. **의사결정 기록(ADR)** — 왜 이 선택, 무엇을 버렸나
5. **협업·공개 리더보드·유지보수** — Anomalib/RAPIDS/secsgem PR, eval set, 살아있는 커밋
