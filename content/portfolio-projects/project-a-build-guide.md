## 1. 환경 설정 & 데이터 이해

### 1.1 WM-811K 데이터 구조 (반드시 먼저 이해)
- 파일: `LSWMD.pkl` (Kaggle `qingyi/wm811k-wafer-map`, CC0) — 약 811,457 행
- 주요 컬럼: `waferMap`(2D array, 값 0=배경/1=정상 die/2=불량 die), `dieSize`, `lotName`, `waferIndex`, `trianTestLabel`, `failureType`
- **9 패턴**: Center, Donut, Edge-Loc, Edge-Ring, Loc, Random, Scratch, Near-full, none
- **주의점 3가지**:
  1. 라벨 있는 건 약 21%(17만), 나머지는 미라벨 → 라벨된 것만 1차로 사용
  2. **극심한 클래스 불균형** — `none`이 압도적, Donut/Near-full은 수백 장
  3. 웨이퍼맵 **크기가 제각각** → 고정 크기로 리사이즈/패딩 필요

### 1.2 환경
🤖 프롬프트:
> "Python 데이터사이언스 프로젝트 환경을 만들어줘. uv 또는 venv 기반, requirements에 numpy/pandas/matplotlib/scikit-learn/torch/torchvision/gradio 포함. WM-811K(LSWMD.pkl)를 읽어 컬럼 구조와 failureType 분포를 출력하는 스크립트도."

✅ 검증: failureType 분포를 직접 보고 불균형 정도를 숫자로 확인 → `decisions.md`에 기록.

## 2. EDA & 클래스 불균형 분석

🤖 프롬프트:
> "라벨된 웨이퍼맵만 필터링하고, 9개 패턴별 (1) 개수 분포 막대그래프 (2) 각 패턴 샘플 웨이퍼맵 5장씩 시각화 (3) dieSize 분포를 그려줘. 패턴별 개수를 표로도."

✅ 검증·기록:
- 각 패턴이 **공간적으로 어떻게 다른지** 눈으로 익힌다(Center는 중심, Edge-Ring은 가장자리 링…). → 이건 3단계 해석의 기반.
- 불균형 비율을 ADR에 기록하고 "어떻게 다룰지"(가중치/증강/리샘플링) 가설을 적는다.

> 💡 차별화 씨앗: 여기서 "패턴이 공간적으로 다르다"를 캡처한 이미지가 나중에 **공정원인 해석**의 근거가 된다.

## 3. 전처리 (웨이퍼맵 → 모델 입력)

🤖 프롬프트:
> "가변 크기 웨이퍼맵을 고정 크기(예: 64×64)로 리사이즈하되, 0/1/2 인코딩의 의미를 보존하는 방식을 제안하고 구현해줘. 종횡비 왜곡을 줄이려면 패딩 후 리사이즈가 나은지 비교해줘. train/val/test 분할은 **lotName 기준 그룹 분할**로 누수를 막아줘."

✅ 검증·기록 (중요):
- **누수 방지**: 같은 lot의 웨이퍼가 train/test에 동시에 들어가면 누수다. `GroupShuffleSplit(groups=lotName)` 사용 확인. → ADR에 "왜 그룹 분할인가" 기록.
- 리사이즈 방식 2개를 비교해 고른 이유를 적는다.

## 4. 베이스라인 → CNN/ViT 분류기

### 4.1 베이스라인 먼저
🤖 프롬프트:
> "단순 베이스라인부터: 웨이퍼맵을 flatten해 RandomForest/로지스틱으로 9클래스 분류하고 balanced accuracy를 측정해줘. 이게 이후 딥러닝 대비 기준선이야."

✅ 검증: 베이스라인 점수를 기록(딥러닝이 정말 나은지 비교 근거).

### 4.2 CNN / ViT
🤖 프롬프트:
> "PyTorch로 작은 CNN(또는 사전학습 ResNet18/ConvNeXt-tiny 전이학습) 9클래스 분류기를 만들어줘. **클래스 불균형은 class-weighted loss로** 처리하고, 학습/검증 곡선과 per-class recall을 출력해줘. 재현성을 위해 seed 고정."

✅ 검증·기록:
- 정확도(accuracy)에 속지 말 것 — `none`만 맞혀도 높게 나온다. **per-class recall과 balanced accuracy**를 본다.
- 어떤 모델/증강을 왜 선택했는지 ADR에 기록. 첫 시도를 버렸다면 그 이유도.

> 💡 (선택, 상급) 미라벨 63만장을 오토인코더/대조학습으로 사전학습 후 fine-tune → "라벨 부족을 self-supervised로 정면돌파" 스토리. 2024~26 트렌드 신호.

## 5. Grad-CAM — 결함 위치 시각화

🤖 프롬프트:
> "학습한 CNN에 Grad-CAM을 붙여, 모델이 어느 영역을 보고 그 패턴으로 분류했는지 히트맵으로 시각화해줘. 패턴별로 올바르게 분류된 사례와 잘못 분류된 사례를 나란히 보여줘."

✅ 검증·기록:
- Grad-CAM이 **실제 불량 영역을 보는지** 확인(Edge-Ring인데 중심을 보면 모델이 엉뚱한 근거로 맞힌 것).
- 이 시각화가 6단계 리포트의 핵심 그림이 된다.

## 6. ⭐ 공정원인 해석 레이어 (이 프로젝트의 심장)

여기가 캐글 클론과 갈리는 지점. 분류 결과를 **공정 도메인 언어로 번역**한다.

### 6.1 패턴 → 공정원인 매핑 룰 (코드로 구현)
아래 표를 `process_cause_map.py`의 규칙으로 만든다. (출처: [portfolio-research.md](../../docs/portfolio-research.md) / [domain-knowledge.md](../domain-knowledge.md) 모듈 2)

| WBM 패턴 | 추정 공정 근본원인 | 구분 단서 |
|---|---|---|
| Center | CMP 균일도 / 플라즈마 식각 중심 과식각 / 척·핀 오염 | 식각 직후 발생=플라즈마, 이전부터=핸들링 |
| Edge-Ring | 식각 / 증착 edge-seal ring / CMP edge 과연마 | seal breach=날카로운 완전 원, CMP=완만한 gradient |
| Edge-Loc | 박막 증착 국소 문제 | edge 근처 국소 클러스터(완전 링 아님) |
| Donut | 툴링 / 식각 marginality | center 깨끗 + 링 |
| Scratch | 핸들링(cassette slot·로봇 end-effector·aligner) | 같은 slot 여러 웨이퍼에 일관된 호=cassette |
| Loc | 국소 입자/결함 | 특정 위치 집중 |
| Random | 본질적 공정 변동(입자 오염) | assignable 원인 없는 노이즈 |
| Near-full | 광범위 공정 실패 | 거의 전면 불량 |

🤖 프롬프트:
> "위 매핑표를 받아서, 분류 결과(패턴)와 웨이퍼맵의 공간 통계(불량 die의 중심/가장자리 분포, 반경별 밀도, 호 형태 여부)를 입력하면 **추정 공정원인 + 근거 + 구분 단서**를 출력하는 함수를 만들어줘. 단정하지 말고 '추정/가능성'으로 표현하게."

✅ 검증·기록 (필수, 윤리):
- 이건 **추정**이지 확정 진단이 아니다. 리포트에 "도메인 문헌 기반 추정, 실제 원인은 fab 데이터 교차검증 필요"라고 명시. (과장 금지 = Not 원칙)
- 매핑의 출처를 각주로 단다.

### 6.2 진단 리포트 생성
🤖 프롬프트:
> "한 장의 웨이퍼맵에 대해: (1) 예측 패턴 + 확신도 (2) Grad-CAM 히트맵 (3) 공간 통계 (4) 추정 공정원인 + 근거 (5) 구분 단서 를 묶은 마크다운/PDF 리포트를 자동 생성하는 함수를 만들어줘."

> 💡 이 리포트 1~2장이 면접에서 보여줄 **결정적 자료**다. "정확도 X%"가 아니라 "Edge-Ring으로 분류된 이 웨이퍼는 가장자리 링 밀도가 높고 내부 경계가 날카로워 식각 seal ring breach가 의심된다"는 해석.

## 7. 평가 — 정직하게

🤖 프롬프트:

## 9. hard-to-fake 신호 마감 (2026 필수)
