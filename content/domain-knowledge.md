# 비전공 IT 취준생을 위한 반도체 도메인 지식 모듈

> 대상: 경영정보/전산 전공으로 삼성DS·SK하이닉스·NVIDIA의 **SW·데이터·IT 직무**를 노리는 사람.
> 목표: 공정을 개발하는 수준이 아니라, **"공정·수율·설비 데이터가 무엇이고 왜 돈(원가·품질)과 직결되는지를 IT 언어로 번역"**할 수 있는 수준.
> 원칙: 얕고 넓게 + **데이터 접점은 깊게**. 모든 개념을 "내 IT 역량과 어떻게 연결되나"로 닫는다.
> 설계 근거: [domain-knowledge-module.md](../docs/domain-knowledge-module.md)

## 모듈 0 — 왜 비전공 IT가 반도체를 알아야 하는가

### 한 문장
반도체 회사에서 **수율(yield) = 이익률**이다. 그리고 수율을 올리는 일의 상당 부분은 **데이터를 모으고·분석하고·시스템으로 자동화하는 일**, 즉 IT의 일이다.

### 관통 메시지 (면접에서 반복해서 써먹을 프레임)
> "저는 반도체 공정을 직접 개발하지는 않습니다. 하지만 공정에서 쏟아지는 데이터를 읽어 **불량의 원인을 찾고, 수율을 끌어올리는 시스템**을 만들 수 있습니다."

### IT/데이터가 수율에 기여하는 지점 지도
```
[공정 설비] --센서/계측 데이터--> [데이터 수집·MES] --분석--> [원인 규명/예측] --제어--> [수율 ↑]
   물리(전공자)              ← 여기부터가 IT/데이터 직무의 영역 →
```
- 설비가 만든 데이터를 **모으는 일** = IT 인프라/MES 직무
- 그 데이터로 **불량을 찾고 예측하는 일** = 데이터/ML 직무
- 분석 결과를 **자동 제어로 되먹이는 일** = SW/시스템 직무

이 모듈 전체는 이 지도의 각 노드를 채워나가는 과정이다.

## 모듈 1 — 반도체 제조 1분 브리핑 [얕고 넓게]

> 목표: 8대 공정을 1분 안에 브리핑하고, "각 단계가 무슨 데이터를 만드는지" 말할 수 있다.

### 1.1 단위 감각: 웨이퍼 → 다이 → 칩 → 패키지
- **웨이퍼(Wafer)**: 실리콘 원판. 여기에 수백~수천 개의 칩을 동시에 만든다.
- **다이(Die)**: 웨이퍼에서 잘라낸 **개별 칩 한 개**. (수율을 셀 때 기본 단위)
- **패키지(Package)**: 다이를 보호하고 외부와 연결하도록 포장한 최종 형태.
- **공정 노드(예: 5nm)**: 회로 최소 선폭. 작을수록 고난도·고집적.

> 💡 데이터 관점: 웨이퍼 1장 = 다이 수백 개 = **데이터 행(row) 수백 개**. "Lot(롯) = 웨이퍼 약 25장" 묶음 단위도 기억.

### 1.2 8대 공정 한 장 요약 (삼성 공식 분류)
| # | 공정 | 무엇을 하나 | 만들어내는 데이터(IT 접점) |
|---|------|------------|--------------------------|
| 1 | 웨이퍼 제조 | 실리콘 원판 생산 | 두께·결정 품질 계측 |
| 2 | 산화(Oxidation) | 절연막(SiO₂) 형성 | 막 두께 계측 |
| 3 | 포토(노광/리소그래피) | 회로 패턴 전사 | **CD(선폭) 계측**, 오버레이 |
| 4 | 식각(Etching) | 불필요한 부분 깎기 | 식각 깊이·균일도 |
| 5 | 증착·이온주입 | 박막 쌓기/불순물 주입 | 농도·두께 |
| 6 | 금속 배선 | 회로 연결(전선) | 저항·연결 검사 |
| 7 | EDS(전기적 검사) | 칩별 양·불량 판정 | **Wafer Bin Map** |
| 8 | 패키징 | 포장·조립 | 조립 추적 데이터 |

> 외울 필요 없다. **"포토에서 CD를 재고, EDS에서 Wafer Bin Map이 나온다"** 정도만 말할 수 있으면 데이터 직무 대화가 된다.

### 1.3 전공정 vs 후공정, 그리고 회사 유형
- **전공정(FAB/Fabrication)**: 웨이퍼 위에 회로 형성 (공정 1~6). 클린룸.
- **후공정(Packaging/Test)**: 자르고·포장·테스트 (공정 7~8). 외주 업체를 **OSAT**라 함.
- **회사 유형 3종**:
  - **IDM**(설계+제조 다 함): 삼성전자 DS, SK하이닉스
  - **팹리스**(설계만): NVIDIA, AMD, 퀄컴
  - **파운드리**(위탁 제조만): TSMC, 삼성 파운드리

> 💡 이게 왜 중요? NVIDIA(팹리스)는 제조 도메인보다 **CS/AI**가 본체다. 삼성·SK(IDM)는 **제조 도메인 + 데이터**를 강하게 본다. → 지원 회사에 따라 이 문서의 강조점이 달라진다(모듈 5).

## 모듈 2 — 수율과 불량 [데이터 접점 — 깊게]

> 목표: 수율 데이터의 구조를 이해하고, "데이터·ML로 수율을 어떻게 올리는지" 구체적으로 말한다.

### 2.1 수율(Yield)이 왜 심장인가
같은 웨이퍼에서 양품이 80% 나오는 회사와 95% 나오는 회사는 **원가가 다르다**. 웨이퍼 1장 가격은 같은데 팔 수 있는 칩 개수가 다르기 때문. 그래서 **수율 1%는 곧 수백억의 이익**이고, 데이터 직무의 존재 이유다.

```
Yield = 양품 다이 수 / 설계상 최대 다이 수
예) 693 / 847 = 81.8%
```

### 2.2 핵심 용어 사전
| 용어 | 의미 |
|------|------|
| **Die / Defect** | 칩 한 개 / 결함(short, open, particle, scratch 등) |
| **D₀ (결함 밀도)** | 단위 면적당 결함 수. 다이가 클수록 결함 포함 확률↑ → 수율↓ |
| **Line Yield vs Die Yield** | 공정 누락 등 큰 손실 vs 작은 random defect 손실 |
| **불량 3분류** | **Random**(이물/particle) · **Parametric**(설비 파라미터 이탈) · **Systematic**(설계-공정 규격 불일치) |
| **Wafer Bin Map (WBM)** | 웨이퍼 위 양·불량 위치 지도. **불량 패턴이 원인 공정을 가리킨다** |
| **OEE (종합설비효율)** | 가용성 × 성능 × 품질. 설비 병목 진단 |

> 💡 WBM은 비전공 데이터 직무자가 가장 잘 써먹는 소재다. "가장자리에 링 모양 불량 = 특정 공정 의심" 식으로 **이미지 패턴 → 원인 공정** 추론이 곧 ML 문제가 된다.

### 2.3 데이터·SW가 수율에 쓰이는 4가지 방식 (면접 어필 포인트)
1. **불량 분류(Defect Classification)**: CNN으로 SEM 이미지·Wafer Map 자동 분류 (예: KLA Klarity)
2. **Commonality 분석**: 불량 발생 시 공통 설비/작업자/공정을 역추적해 원인 규명
3. **수율 예측 모델**: XGBoost로 die별 합·불 예측, killer defect 필터링, PCA 차원축소
4. **SPC(통계적 공정관리)**: 관리도로 공정 이상을 실시간 감지

> **실무 도구**: JMP, Spotfire, Minitab(통계), SQL, Python. SK하이닉스는 "JMP/Spotfire 이상탐지·SPC 경험을 데이터와 연결하라"고 명시.

## 모듈 3 — 스마트팩토리 IT 스택 [IT 직무 핵심 — 깊게]

> 목표: 비전공 IT 직무자가 **가장 강하게 어필**할 수 있는 영역. 채용공고가 직접 Java/Python/C#/SQL을 요구한다.

### 3.1 ERP–MES–제어 3계층
```
ERP   (계획: 무엇을 얼마나 만들까)        ← 경영
 ↓
MES   (실행: 지금 라인에서 무슨 일이)      ← IT 직무의 핵심
 ↓
제어   (설비: 밸브 열고 온도 맞추고)        ← 설비/물리
```
- **MES (Manufacturing Execution System)**: ERP와 설비 사이의 가교. 원자재→완제품을 **실시간 추적·문서화·제어**.
- 국제표준 **MESA-11**이 11대 기능 정의: 자원할당, 일정관리, 데이터수집, 품질관리, 공정관리, **제품추적/계보(genealogy)** 등.
- 반도체에서 특히 중요한 건 **추적성**: "이 불량 칩이 어느 설비·어느 시각에 처리됐나"를 역추적.

### 3.2 CIM / EES
- **CIM (Computer Integrated Manufacturing)**: 공장 자동화 통합 시스템. 채용공고상 "CIM 엔지니어 = 제조 IT 시스템 개발/유지보수". 스택: Java/Python/C#/.NET/Oracle/SQL.
- **EES (Equipment Engineering System)**: 설비 엔지니어링 시스템(아래 약어들의 묶음).

### 3.3 SECS/GEM — 비전공자가 알면 강력한 차별점
- **SECS/GEM** = HOST(MES)와 **설비 간 통신 프로토콜**(SEMI 표준 E5/E30/E37 등).
- IT/SW 직무 지원자라면 **이름·역할 수준은 반드시** 알아두자. 다수 MES 개발 공고가 *우대사항*으로 명시.

### 3.4 한 줄 약어 사전 (이름·역할만)
| 약어 | 역할 |
|------|------|
| **FDC** | Fault Detection & Classification — 설비 실시간 이상탐지 |
| **SPC** | Statistical Process Control — 통계적 공정관리(관리도) |
| **APC / R2R** | Advanced Process Control / Run-to-Run — 자동 공정제어(되먹임) |
| **VM** | Virtual Metrology — 가상계측(모듈 4) |
| **YMS / RMS** | Yield / Recipe Management System |

> 💡 면접 팁: 이 약어들을 다 깊이 알 필요 없다. "MES 위에서 FDC·SPC·APC가 돌고, 설비와는 SECS/GEM으로 통신한다"는 **그림 한 장**을 말할 수 있으면 비전공자로서 충분히 인상적이다.

## 모듈 4 — 반도체 데이터 사이언스의 특수성 [DS 직무 — 깊게]

> 목표: "일반 비즈니스 데이터와 뭐가 다른가"를 설명해 **도메인을 이해한 데이터 사이언티스트**로 보이게 한다.

### 4.1 가상계측(Virtual Metrology, VM) + Large P / Small N
- 비용·시간 때문에 **한 Lot(웨이퍼 ~25장) 중 1~2장(약 1%)만 실측**한다.
- 나머지는 **설비 센서 데이터(온도·압력·가스·파워)로 품질을 예측** → 이것이 VM(soft sensor).
- 구조의 특수성: 센서 수백 개 × 시간 window → **변수(P) 수천 개**인데 **실측 관측치(N)는 극소수**. 일반 ML과 정반대(보통 N ≫ P).

### 4.2 공정 시계열 데이터의 특성
- ① 웨이퍼마다 sequence 길이가 다름 → **alignment 안 맞음**
- ② 공정 간 선후관계·교호작용 존재
- ③ **process drift**: 설비 노후화로 값이 서서히 이동 → 모델 재학습 필요

### 4.3 FDC — 불량 탐지·분류
- 설비 센서 시계열로 이상을 실시간 탐지·분류. CNN으로 Wafer Map/이미지 분류가 대표.

### 4.4 멀티소스 통합과 근본원인 추적
- 인라인 결함·계측 + 장비 센서 + 전기 테스트(EDS) + 조립 추적을 **wafer→die→lot 계층**으로 통합해야 근본원인이 보인다.

> **꼭 기억할 2종 과제**: **VM(가상계측)** + **FDC(불량 탐지/분류)**. 데이터 직무 면접에서 이 둘을 언급하면 도메인 이해가 드러난다.

## 모듈 5 — 회사별 맞춤 [지원 직전]

### 5.1 강조점 비교
| | 삼성 DS / SK하이닉스 (IDM·메모리) | NVIDIA (팹리스·GPU SW) |
|---|---|---|
| 도메인 요구 | **제조 도메인 + 데이터**를 강하게. SK는 "공정 이해 있는 SW엔지니어·T형 인재" | CS·AI가 본체. 반도체 도메인은 **공급망/제조데이터 직무에서만 가산점** |
| 데이터 직무 무게 | 공정·품질·수율 분석(JMP/Minitab), VM/APC | ML/DL·통계 + SQL·파이프라인. 제조 도메인은 "빠르게 습득" 수준 |
| 코테 언어 | 삼성 SW: C/C++/Java/Python / SK IT: **C/C++만** | C/C++/Python (시스템 디자인 비중↑) |

### 5.2 시의성 키워드 (자소서·면접에 녹이기)
- **삼성·SK**: HBM, CXL, PIM, EUV, DRAM/NAND, MR-MUF 패키징, "Total AI Memory"
- **NVIDIA**: CUDA, Triton, LLM/GenAI, GPU 아키텍처, 데이터센터 워크로드

### 5.3 관통 프레임 (자소서·면접 공통)
모든 도메인 경험을 이 5단계로 서술하면 "데이터로 문제 푸는 사람"으로 보인다:
```
Issue(문제) → Root Cause(원인) → Hypothesis(가설) → Test(검증) → Result(정량 성과)
```
현직자·합격 자소서가 공통으로 강조하는 건 **지식 나열이 아니라 이 문제해결 논리 구조**다.

## 부록 — "여기까지는 과함" 체크리스트

비전공 IT 직무자가 **깊이 안 가도 되는** 영역 (이름 수준만):
- ❌ 소자물리·고체물리·양자역학
- ❌ 회로 설계(Analog/Digital), Verilog/VHDL, EDA 툴(Cadence)
- ❌ TCAD/SPICE 시뮬레이션, 공정 레시피 튜닝
- ❌ 공정별 화학·재료 메커니즘 디테일
- ❌ EUV 노광 광학·OPC 알고리즘 내부

→ FinFET/GAA·EUV는 **이름만**. 대신 **수율·불량 데이터 구조, MES/CIM/SECS-GEM, VM/FDC, SQL/ML**에 시간을 쏟아라.
