# 포트폴리오 샘플 — SK하이닉스 수율/공정 데이터분석 직무

> 이 문서는 **하나의 직무를 골라 "증명해야 할 역량 → hard-to-fake 포트폴리오"로 변환한 샘플**이다.
> 다른 직무도 같은 틀(① JD에서 역량 추출 → ② 검증 가능한 프로젝트 설계 → ③ 스토리)로 복제할 수 있다.
> 근거: [jd-reverse-mapping.md](../../docs/jd-reverse-mapping.md), [portfolio-hire-cases.md](../../docs/portfolio-hire-cases.md), [domain-knowledge-module.md](../../docs/domain-knowledge-module.md)

## 0. 왜 이 직무인가 (경영정보/전산 적합도 ★★★★)
- SK하이닉스 신입 IT 직무기술서 모집전공에 **경영정보학 명시** → 정공법.
- 공정 데이터 분석은 "통계+코딩+체계적 문제해결"이 핵심 → 비전공자도 **포트폴리오로 증명 가능한** 영역(탐구2 검증).
- 단, 반도체 데이터의 특수성(VM/FDC, Large P·Small N)을 아는 것이 변별 요소.

## 1. JD에서 추출한 "증명해야 할 역량"
| # | 역량 | 출처(JD) | 증명 난이도 |
|---|------|---------|-----------|
| C1 | **통계 + 코딩(Python/SQL)** 으로 데이터 핸들링 | 필수 | 중 |
| C2 | **불량/이상 탐지·분류** (ML/DL) | 우대 | 높음 |
| C3 | **공정 데이터 특수성 이해** (시계열·계측·VM) | 도메인 | 높음 |
| C4 | **현업과 협업·소통**, 문제 정의력 | 우대 | 높음(혼자선 증명 불가) |
| C5 | JMP/Spotfire/SPC 등 분석 도구 | 우대 | 낮음 |

> 핵심 통찰: C1·C5는 누구나 증명할 수 있어 **변별력이 낮다**. 합격을 가르는 건 **C2·C3·C4** — 그래서 포트폴리오는 여기에 hard-to-fake 신호를 집중해야 한다.

## 2. 포트폴리오 설계 — "Wafer Map 불량 패턴 분류 + 수율 인사이트 대시보드"

### 2.1 프로젝트 한 줄 정의
> 공개 반도체 데이터셋(WM-811K Wafer Map)으로 **불량 패턴을 자동 분류하는 CNN 모델**을 만들고, 분류 결과를 **수율 저하 원인 가설로 연결하는 대시보드**까지 배포한다.

- **왜 hard-to-fake한가**: 실제 반도체 도메인 데이터(WM-811K, 공개) + 모델 성능 수치 + 실제 배포 + 도메인 해석(WBM 패턴↔원인 공정)을 한 줄로 엮으면 "막연한 토이프로젝트"와 명확히 구분된다.
- **데이터셋**: WM-811K (811,457개 실제 wafer map, 9개 불량 패턴 라벨) — Kaggle/공개. 진짜 반도체 데이터라는 점이 도메인 신호.

### 2.2 역량 커버리지 매핑
| 역량 | 이 프로젝트에서 어떻게 증명되나 |
|------|------------------------------|
| C1 통계+코딩 | Python(pandas/numpy) 전처리, 클래스 불균형 처리, SQL로 집계 |
| C2 불량 분류 ML | CNN 분류기(9-class), 혼동행렬·F1, 클래스 불균형(SMOTE/weighting) |
| C3 공정 데이터 이해 | WBM 패턴(Center/Edge-Ring/Scratch 등)을 **원인 공정 가설로 해석**(모듈2·4 활용) |
| C4 협업·문제정의 | (보강책 ↓) 오픈소스 기여 or 2인 협업으로 git 협업 흔적 만들기 |
| C5 도구 | 결과를 Spotfire/Tableau 또는 Streamlit 대시보드로 |

### 2.3 hard-to-fake 4신호 심기 (2026 시장 핵심)
2026년엔 "deploy된 앱"만으론 부족하다. 다음을 의도적으로 심는다:
1. **협업 커밋** — 동료 1명과 페어로 진행하거나, 기존 wafer-map 오픈소스에 PR 1건 기여 → 타인 이름이 git에 남게.
2. **살아있는 배포 + 운영 흔적** — Streamlit Cloud/HF Spaces에 배포, README에 환경변수·재현 방법.
3. **개발자다운 git 히스토리** — atomic 커밋, 브랜치/머지. "initial commit에 5천 줄" 금지.
4. **레퍼런스/리뷰** — 스터디·부트캠프 멘토에게 코드리뷰 받은 흔적(PR 코멘트).

### 2.4 4주 빌드 플랜
| 주차 | 산출물 |
|------|--------|
| 1주 | WM-811K EDA, 클래스 불균형 분석, 베이스라인(로지스틱/RandomForest) + SQL 집계 |
| 2주 | CNN 분류기 학습, 혼동행렬/F1, 잘못 분류된 패턴 오류분석 |
| 3주 | **도메인 해석 레이어** — 각 불량 패턴 → 의심 공정 가설표(모듈 활용), Commonality 관점 |
| 4주 | Streamlit 대시보드 배포 + README/디자인독 + 30초 데모 영상 |

### 2.5 절대 하지 말 것 (Not 일관)
- ❌ 성능 수치 조작("hiring managers can smell fake numbers")
- ❌ AI가 통째로 짠 코드를 이해 없이 붙여넣기 → 면접 후속질문에서 붕괴
- ❌ 실데이터 없이 가짜 시나리오만 — 반드시 공개 실데이터 사용

## 3. 스토리 — 자소서·면접 직무직결 (STAR + 5단계 프레임)

### 3.1 자소서 불릿 (Action+scope+tool+metric+outcome+proof)
> "WM-811K 81만 건 wafer map을 **CNN으로 9종 불량 패턴 분류**(macro-F1 0.8X)하고, Edge-Ring 패턴을 **식각 공정 불균일 가설**로 연결해 Streamlit 대시보드로 배포했습니다. [GitHub/데모 링크]"

### 3.2 면접 예상 질문 → 답 뼈대 (Issue→Root Cause→Hypothesis→Test→Result)
- "왜 이 프로젝트를?" → 수율=이익, 불량 패턴이 원인 공정을 가리킨다는 점에 끌림(모듈 0·2).
- "클래스 불균형은 어떻게?" → 분포 제시 → weighting/SMOTE 비교 → F1로 검증.
- "이 패턴이 왜 그 공정?" → WBM 도메인 해석(모듈 2.2/4.4). **모르면 솔직히 + 논리적 접근 제시**.
- "실무 데이터는 더 다르다" → VM/Large P·Small N·process drift 언급(모듈 4)으로 도메인 이해 입증.

### 3.3 C4(협업) 보강 멘트
> "혼자 만든 게 아니라 OO와 페어로 진행하며 코드리뷰를 주고받았고, 그 과정에서 [구체 충돌·결정]을 겪었습니다." → 면접관이 보고 싶어 하는 "압박 속 협업" 신호.

## 4. 이 샘플을 다른 직무로 복제하는 법
1. **JD 1~3개** 수집 → 1번 표처럼 역량 추출, **변별력 낮은 역량 vs 가르는 역량** 구분.
2. 가르는 역량에 **hard-to-fake 프로젝트** 1개 집중 설계(실데이터+성능+배포+도메인 해석+협업).
3. 2.3의 **4신호**를 의도적으로 심기.
4. 3번처럼 STAR + 5단계 프레임으로 스토리화.
